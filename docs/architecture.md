# المعمارية التقنية

## الطبقات

```
┌─────────────────────────────────────────────┐
│ apps/web        واجهة المنصة (PWA، RTL، بحث) │
├─────────────────────────────────────────────┤
│ sims/*          محاكاة مستقلة = نموذج + عرض  │
├──────────────┬──────────────────────────────┤
│ packages/ui  │ مكونات تحكم معيارية بإتاحة    │
├──────────────┴──────────────────────────────┤
│ packages/core │ Property + ساعة ثابتة + حالة │
└─────────────────────────────────────────────┘
```

## قرارات معمارية (ADR مبسطة)

| القرار | البدائل | السبب |
|--------|---------|-------|
| نمط مراقب (Property) بدل إطار UI ثقيل في النواة | React state / signals | النموذج يجب أن يبقى صرفاً قابلاً للاختبار والتشغيل دون متصفح |
| ساعة بخطوات ثابتة (fixed timestep) | خطوة بطول الإطار | نتائج عددية قابلة للتكرار واختبارات علمية حتمية |
| Web Components للمكونات | React/Vue مخصص | عمل في أي سياق تضمين (مثل iframe) دون تعارض أطر |
| حالة مشتركة بترميز Base64 في الرابط | قاعدة بيانات وحسابات | جوهر المشروع: لا خوادم ولا حسابات |
| Monorepo بمساحات npm | مستودعات متعددة | إعادة استخدام فورية وبوابة جودة موحدة |

## تدفق البيانات

النموذج يغيّر `Property` → العرض والوصف الصوتي والتقييم يشتركون → لا يكتب العرض في النموذج أبداً.
مشاركة الحالة: `getState() → encodeState() → ?state=...` وتسترجعها `setState` بشكل متماثل (مختبَر).

## الأداء

- ميزانية بدء تفاعل أول: < 3 ثوانٍ على شبكة 3G.
- 60 إطاراً/ث على هاتف متوسط؛ وضع أداء منخفض يخفض الدقة تلقائياً دون المساس بالنموذج.
